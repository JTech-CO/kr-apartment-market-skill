# 데이터 원천 및 수집 정책

- 문서 버전: 1.0.0
- 기준일: 2026-08-18
- 기본 시간대: Asia/Seoul

## 1. 목적

이 문서는 KR Apartment Market의 데이터 원천, 접근 등급, 수집·보관·재배포 허용 범위, 최신성 처리, 정합성 회복 절차를 규정한다. 구현체는 화면에 공개되어 있다는 이유만으로 자동 수집 권한이 있다고 간주하지 않는다.

## 2. 접근 등급

| `access_mode` | 의미 | 수집 | 캐시 | 파생 지표 | 사용자 표시 |
|---|---|---:|---:|---:|---:|
| `PUBLIC_OPEN` | 공개 API이며 이용 범위가 확인됨 | 허용 | 허용 | 허용 | 허용 |
| `AUTHORIZED_INGEST` | 계약·서면 허가·공식 API 조건으로 승인됨 | 승인 범위 | 승인 범위 | 승인 범위 | 승인 범위 |
| `LINK_OUT_ONLY` | 원문 이동만 허용하는 보수적 기본값 | 금지 | 금지 | 금지 | 링크만 |
| `DISABLED` | 사용 중지 또는 권한 불명확 | 금지 | 금지 | 금지 | 금지 |

권한은 `ref.data_source`에 저장하며, 애플리케이션 코드의 조건문만으로 우회할 수 없게 한다. `LINK_OUT_ONLY` 원천에 대해 `can_ingest`, `can_cache`, `can_redistribute`, `can_derive`는 모두 `false`여야 한다.

## 3. V1 핵심 원천

### 3.1 국토교통부 아파트 매매 실거래 공개 API

- 내부 원천 코드: `molit_public`
- 데이터셋 코드: `MOLIT_APT_SALE`
- 접근 등급: `PUBLIC_OPEN`
- 전송 형식: REST/XML
- 대표 조회 키:
  - `LAWD_CD`: 법정동 코드 앞 5자리
  - `DEAL_YMD`: 계약 연월 `YYYYMM`
- 기본 용도:
  - 아파트 매매 실거래
  - 계약일, 거래금액, 전용면적, 층, 건축연도
  - 취소·정정 관련 필드가 제공되는 경우 상태 반영
- 구현 원칙:
  - API 응답을 `ingest.raw_record`에 먼저 기록한다.
  - 파싱 후 `market.real_estate_transaction`에 업서트한다.
  - API 서비스 키는 데이터베이스나 MCP 응답에 저장하지 않는다.
  - 공공데이터포털의 최신 이용 조건과 트래픽 승인을 배포 전에 다시 확인한다.

### 3.2 국토교통부 아파트 전월세 실거래 공개 API

- 내부 원천 코드: `molit_public`
- 데이터셋 코드: `MOLIT_APT_RENT`
- 접근 등급: `PUBLIC_OPEN`
- 기본 용도:
  - 전세 보증금
  - 월세 보증금과 월세액
  - 계약일, 전용면적, 층
- 구현 원칙:
  - 전세와 월세를 `trade_type`으로 분리한다.
  - 월세 거래를 전세가율 계산에 섞지 않는다.
  - 갱신계약 여부 등 원천 필드가 있으면 원본과 정규화 필드를 모두 보존한다.

### 3.3 국토교통부 실거래가 공개시스템

- 내부 원천 코드: `molit_rt`
- 접근 등급: 기본 `LINK_OUT_ONLY`
- 기본 용도:
  - 사용자가 공식 원문 화면을 확인할 수 있는 검증된 링크 제공
  - API 결과와 웹 화면의 수치가 충돌할 때 운영자가 수동 검증
- 제한:
  - 범용 웹 크롤러로 페이지 전체를 저장하지 않는다.
  - URL은 `ref.source_link_rule`의 allowlist와 검증된 템플릿으로만 만든다.

### 3.4 공공데이터포털

- 내부 원천 코드: `data_go_kr`
- 접근 등급: 데이터 자체가 아니라 문서 링크 기준 `LINK_OUT_ONLY`
- 기본 용도:
  - API 명세와 이용 조건으로 이동
  - 데이터셋 메타데이터 확인

## 4. 아파트Me 정책

- 내부 원천 코드: `apt2me`
- 기본 접근 등급: `LINK_OUT_ONLY`
- V1에서 허용:
  - 아파트Me 기능군을 제품 벤치마크로 참고
  - 검증된 홈페이지 또는 명시적으로 매핑된 페이지로 이동
  - 링크 제목에 “아파트Me에서 확인” 표시
- V1에서 금지:
  - 페이지 전체 또는 표·랭킹의 주기적 자동 수집
  - 아파트Me 데이터베이스를 복제하는 저장
  - 아파트Me 고유 산식·랭킹을 자체 계산 결과인 것처럼 재배포
  - robots 차단, 인증, 레이트리밋 또는 기술적 제한 우회
  - `content_ingested=true`로 응답
- 승인 어댑터 전환 조건:
  1. 운영 주체와 범위가 명시된 계약 또는 서면 허가
  2. 수집 대상 필드와 API/피드의 공식 기술 명세
  3. 호출량, 캐시 기간, 파생 지표, 재배포 범위
  4. 출처 표기와 철회·종료 절차
  5. 개인정보와 사용자 계정 데이터 처리 범위
  6. 내부 원천 레지스트리의 `access_mode=AUTHORIZED_INGEST` 변경 승인

승인 전환은 데이터베이스 마이그레이션 또는 관리 승인 로그를 동반해야 하며, 단순 환경변수 변경만으로 열리지 않게 한다.

## 5. “실시간”과 최신성

부동산 실거래는 계약 직후 즉시 체결 스트림으로 공개되는 데이터가 아니다. 신고 지연, 정정, 계약 취소가 존재하므로 제품은 다음 시각을 구분한다.

| 필드 | 의미 |
|---|---|
| `contract_date` | 실제 계약일 |
| `reported_at` | 원천이 제공하는 신고·등재 시각, 없으면 `null` |
| `source_watermark_at` | 원천 데이터가 최신이라고 판단한 기준 시각 |
| `collected_at` | 수집기가 데이터를 받은 시각 |
| `computed_at` | 파생 지표가 계산된 시각 |
| `answered_at` | MCP가 응답한 시각 |

사용자 표현은 “최신 신고·공개 실거래”를 기본으로 한다. “오늘 거래” 대신 “오늘 새로 확인된 신고 거래”라고 표현한다.

## 6. 수집 전략

### 6.1 초기 적재

1. 대상 시도·시군구와 시작 연월을 정의한다.
2. `region × contract_month × dataset` 단위 작업을 생성한다.
3. 원본 응답을 변경하지 않고 `ingest.raw_record.payload`에 저장한다.
4. 파서 버전을 기록하고 정규화한다.
5. 단지 매칭 신뢰도가 낮은 레코드는 보류 큐로 보낸다.
6. 거래 상태와 금액 제약을 통과한 레코드만 활성 집계에 포함한다.

### 6.2 일일 증분 적재

기본 재조회 범위:

- 현재 계약 월
- 직전 계약 월
- 2개월 전 계약 월

신고 지연과 취소·정정을 고려해 최근 3개월을 반복 조회한다. 운영 데이터에서 지연 분포를 측정한 뒤 6개월까지 확대할 수 있다.

### 6.3 정합성 재검사

- 최근 12개월: 주 1회 전체 재조정
- 12개월 이전: 월 1회 또는 원천 변경 감지 시
- 원본 해시 변경: revision 생성
- 취소 상태 변경: 기존 행을 물리 삭제하지 않고 `record_status=CANCELED`
- 재활성화 또는 정정: revision을 추가하고 현재 행만 갱신

## 7. 단지 식별과 매핑

원천 단지명은 안정적 ID가 아니다. 다음 조합으로 후보를 만든다.

1. 법정동 또는 지역 코드
2. 정규화 단지명
3. 지번·도로명 주소
4. 전용면적 분포
5. 건축연도
6. 외부 원천 식별자

자동 매핑 임계값 미만이면 `MAPPING_CONFIDENCE_LOW`로 처리한다. 동일 이름의 단지를 임의로 합치지 않는다.

## 8. 원천 필드 정규화

| 정규 필드 | 원천 예시 | 규칙 |
|---|---|---|
| `price_krw` | 거래금액(만원) | 공백·쉼표 제거 후 ×10,000 |
| `deposit_krw` | 보증금액(만원) | ×10,000 |
| `monthly_rent_krw` | 월세금액(만원) | ×10,000 |
| `exclusive_area_m2` | 전용면적 | 원본 소수 정밀도 유지 |
| `floor` | 층 | 지하층 표기를 정규화하되 원본 보존 |
| `contract_date` | 년·월·일 | 유효한 한국 날짜로 조합 |
| `record_status` | 해제 여부 | `VALID` 또는 `CANCELED` |
| `transaction_method` | 거래유형 | `BROKERED`, `DIRECT`, `UNKNOWN` |

원천값을 해석하지 못하면 0으로 채우지 않고 `null`과 품질 경고를 사용한다.

## 9. 데이터 품질 규칙

### 차단 오류

- 날짜 파싱 실패
- 음수 가격 또는 음수 면적
- 거래 유형별 필수 금액 누락
- 존재하지 않는 지역 코드
- 원천 권한이 `LINK_OUT_ONLY`인데 raw record가 수집됨

### 경고 오류

- 단지 매핑 신뢰도 낮음
- 층 또는 건축연도 누락
- 동일 자연키 후보 다수
- 극단값 후보
- 현재 월 미완결

극단값은 삭제 근거가 아니라 품질 플래그다. 신고된 값은 보존하고, 지표에는 포함 여부와 정책 버전을 기록한다.

## 10. 보관과 삭제

| 계층 | 권장 보관 |
|---|---|
| 공개 API 원본 | 이용 조건이 허용하는 범위에서 장기 보관 |
| 정규화 거래 | 장기 보관, revision 포함 |
| 파생 스냅샷 | 24개월 후 저빈도 스토리지 또는 재계산 정책 |
| MCP 관측 로그 | 30~90일, 원문 질의·전체 응답 미저장 |
| OAuth idempotency 응답 | 기본 24시간 |
| 삭제된 관심 항목 | 30일 soft delete 후 물리 삭제 가능 |

법적·계약상 보관 기간이 더 짧으면 해당 조건이 우선한다.

## 11. 장애 시 동작

- 원천 장애: 마지막 정상 캐시와 `DELAYED` 또는 `UNAVAILABLE` 표시
- 일부 지역 실패: 성공 지역과 실패 지역을 분리
- 파서 실패: 기존 정상 데이터를 유지하고 새 배치를 공개하지 않음
- 권한 철회: 해당 원천 어댑터 중지, 캐시 격리, 필요 시 삭제 작업 생성
- 링크 검증 실패: URL 추측 금지, 링크 생략
